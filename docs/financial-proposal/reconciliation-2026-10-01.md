## ผลที่มีนัยต่อการนำมาใช้

- Critical หากทับ patch ทั้งชุด: main.ts ถอด Origin enforcement และ bounded proxy CIDRs; IdentityModule ถอด SessionService/InvitationController/readiness; route policy ทำ capabilities/jobs หาย. ต้องรักษา S1–F1 และเพิ่มเฉพาะ financial endpoints ที่ผ่าน current authority.
- Important: proposal ลบ F1 readiness calls/providers และเริ่ม API scheduler ทันที แม้ accounting hard-stop ยังกันเอกสารใหม่. ต้องคง F1 gate ทุก write/send และสร้าง FinancialApplicationService ตาม public contract ก่อน controller/worker wiring.
- Important: OperationsService รุ่น proposal ย้อน pagination/aggregate/read-by-ID ของ Q1/U1 และ jobId ของ U2. FinancialPdfPreview ใช้หน้าแรก collection หา ID จึงเปิดเอกสารเก่าในหน้าถัดไปไม่ได้ ต้อง direct scoped lookup.
- Important: payment approval ต้องรับ selected paymentIds ตาม F2 ไม่ approve pending ทั้งหมดที่เพิ่มเข้ามาระหว่างผู้ใช้ดูหน้า; คง cycle→payments row lock, full settlement, uniqueness/audit และเพิ่ม idempotency ของ evidence submit. Self-correction ปัจจุบัน throw409 แต่ brief ต้อง403.

- Q3 ต้องใช้ exact midnight + continuity/reset/mapping-conflict checks ต่อไป; financial boundary ใช้ค่าจริงภายใน ±5 นาทีเฉพาะ policy การเงิน. การที่ financial candidateครบไม่ได้ทำให้ Q3 daily qualityครบ และห้ามใช้ daily summary เติม baseline. rawเกิน90วันต้อง restore/blockตามD1/ADR0011 ไม่แสดงข้อมูลเก่าทันที.
- PDF ต้องคง actual document UUID แยกจากเลขเอกสาร, immutable snapshot/artifact และ bytes เดียวใน preview/download/email. Missing original ต้อง unavailable ไม่ render จากข้อมูลปัจจุบัน. ข้อเสนอไม่อนุมัติสูตรภาษี/rounding/เลขเอกสาร; numbering timezone และ old publicId links ต้อง reconcile.
- Candidate migrations 011/013/015/016/017 ยังไม่ register/apply. คง migration009เดิม รวม current018–021 และ D1ที่เพิ่มภายหลัง; ทดสอบ ledger/checksum, duplicate preflight, old rates, immutable history บนfresh+upgradeownedDBก่อนขอใช้จริง.

## ลำดับหลังตรวจและก่อน active integration

1. รักษา reject files และเตรียม additive integration patch ตาม adapt rows ภายหลัง explicit proposal approval; เพิ่ม FinancialApplicationService API ที่ถูกกำหนดในbrief โดยคง current F1 readiness verifierเป็นnull/flagsปิด.
