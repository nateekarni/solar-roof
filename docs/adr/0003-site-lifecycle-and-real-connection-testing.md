# 3. Site Lifecycle Management and Real Gateway Connection Verification

## Status
Accepted

## Context
1. ในกระบวนการลงทะเบียนไซต์งาน (Site Registration Wizard Step 3) การทดสอบสัญญาณการเชื่อมต่อเดิมเป็นแบบจำลองเวลา (Mock Simulation ด้วย `setTimeout`) ซึ่งไม่สะท้อนสถานะการเชื่อมต่อจริงของเกตเวย์ ทำให้ไม่สามารถตรวจจับปัญหาทางเครือข่าย หรือความผิดพลาดของการระบุ Endpoint/MQTT Topic ได้ก่อนการเริ่มรับส่งข้อมูล
2. เมื่อผู้ใช้กรอกข้อมูลสร้างไซต์งาน มีโอกาสเกิดความผิดพลาดในการส่งข้อมูลซ้ำ (Accidental Double Submission) หรือข้อมูลหมายเลขซีเรียลของอุปกรณ์ซ้ำกับในระบบ ซึ่งเดิมไม่มีการครอบคลุมด้วย Database Transaction ส่งผลให้เกิดข้อผิดพลาดฐานข้อมูลและข้อมูลไม่สอดคล้องกัน (Orphaned Rows)
3. การจัดการไซต์งานในระบบยังขาดความสามารถในการแก้ไขข้อมูลหลังการสร้าง (Edit Site) และนโยบายการลบไซต์งานยังไม่มีมาตรการปกป้องข้อมูลประวัติทางสัญญาและรอบบิล ซึ่งอาจส่งผลกระทบต่อความสมบูรณ์ของข้อมูลทางการเงิน (Financial Integrity)

## Decision
1. **การตรวจสอบสัญญาณการเชื่อมต่อจริง (Real Connection Verification)**:
   - สร้าง Endpoint `POST /v1/sites/test-connection` เพื่อทดสอบสัญญาณจริง:
     - สำหรับ MQTT: เชื่อมต่อ Broker และตรวจสอบการสื่อสารบน Topic พร้อมวัดค่า Latency
     - สำหรับ Modbus TCP: ทดสอบการเปิด TCP Socket ไปยัง Host/IP และ Port (Timeout 3 วินาที)
   - หากเชื่อมต่อไม่สำเร็จ ระบบจะแสดงผลข้อผิดพลาดจริง แต่ยังอนุญาตให้ผู้ใช้บันทึกไซต์งานล่วงหน้าได้โดยกำหนดสถานะเป็น `offline` เพื่อรองรับกระบวนการเตรียมการติดตั้งก่อนจ่ายไฟจริง
2. **การป้องกันข้อผิดพลาดและความสมบูรณ์ของธุรกรรม (Transaction Safety & Duplicate Check)**:
   - ตรวจสอบความซ้ำของ `serial_number` ก่อนเริ่มบันทึก
   - ครอบคลุมการบันทึกข้อมูลตาราง `sites`, `gateways`, `devices`, `billing_meters`, และ `register_mapping_versions` ด้วย Database Transaction (`BEGIN...COMMIT/ROLLBACK`)
   - ปรับการจัดการเหตุการณ์ในฟอร์มหน้าบ้าน (Prevent premature submit on Enter key) และปรับแคช Next.js ของหน้าไซต์งานเป็น `no-store` เพื่อให้ข้อมูลอัปเดตทันที
3. **การจัดการวงจรชีวิตและการลบไซต์งานแบบปลอดภัย (Safe Deletion & Archival Policy)**:
   - เพิ่ม Action Options "แก้ไข" (Edit) และ "ลบ" (Delete) ในหน้ารายการไซต์งาน
   - หากไซต์งานมีสัญญา (Contracts) หรือรอบบิล (Billing Cycles) ผูกอยู่ จะระงับการลบถาวร และเปิดให้ระงับการใช้งาน (Archive: สถานะเป็น `archived`/`offline`) เพื่อรักษาประวัติทางบัญชี
   - หากเป็นไซต์งานใหม่ที่ยังไม่มีสัญญาหรือรอบบิลผูกพัน อนุญาตให้ลบถาวร (Hard Delete) พร้อม Cascade ข้อมูลอุปกรณ์และโทรมาตรที่เกี่ยวข้องทั้งหมด

## Consequences
- ช่างเทคนิคและผู้ดูแลระบบสามารถตรวจสอบความถูกต้องของการสื่อสารเกตเวย์ได้ทันทีตั้งแต่ขั้นตอนสร้างไซต์งาน
- ป้องกันข้อมูลสูญหายหรือสถานะไซต์งานค้างในฐานข้อมูลเมื่อเกิดข้อผิดพลาด
- ข้อมูลทางบัญชีและสัญญามีความปลอดภัย ไม่ถูกลบโดยไม่ตั้งใจ
- หน้ารายการไซต์งานสะท้อนการเปลี่ยนแปลงทันทีเมื่อมีการเพิ่ม แก้ไข หรือลบไซต์งาน
