# 10. Contracts PDF Preview, Billing Split-View Modal, and Evidence Verification

## Status
Accepted

## Context
1. **ข้อผิดพลาดในการนำทางของ School Detail Modal**:
   - เมื่อผู้ใช้กดปุ่ม "ดูรายการไซต์พลังงาน" ใน `SchoolDetailModal` ระบบพยายามส่งคำขอไปยังเส้นทาง `/operations?resource=sites` ซึ่งไม่มีอยู่จริง ส่งผลให้เกิดข้อผิดพลาด 404 (เส้นทางที่ถูกต้องคือ `/sites`)
   - โมดอลรายละเอียดต่าง ๆ มีเส้นแบ่งขอบที่ซ้ำซ้อน และมีปุ่ม "ปิดหน้าต่าง" ที่ส่วนท้าย ทั้งที่มีปุ่มปิด `X` ที่มุมขวาบนอยู่แล้ว
2. **ขนาดความกว้างของโมดอลสัญญาณสด (Site Telemetry Dialog)**:
   - โมดอลสัญญาณสดมีขนาดจำกัดอยู่ที่ `sm:max-w-lg` เนื่องจากข้อจำกัดดั้งเดิมของ Shadcn Dialog ทำให้ข้อมูลการวัดและตาราง Raw Modbus Registers ถูกบีบอัดจนอ่านได้ยากบนหน้าจอเดสก์ท็อป
3. **การแสดงผลเอกสารสัญญา PPA**:
   - ผู้ใช้ต้องการให้โมดอลดูสัญญาเปลี่ยนโฉมเป็นหน้าแสดงตัวอย่าง PDF กระดาษ A4 เสมือนจริง ร่างเงื่อนไขระยะเวลา 20 ปี, สเปกทางเทคนิค, และกล่องลายเซ็นของคู่สัญญา 2 ฝ่าย (ผู้ให้บริการ และ สถานศึกษา) เพื่อรองรับการลงนามทั้งแบบระบบดิจิทัลหรือเซ็นด้วยมือในอนาคต
4. **การเลือกดูรอบบิลในเอกสารทางการเงิน**:
   - เมื่อเลือกดูใบแจ้งหนี้หรือใบเสร็จรับเงิน ผู้ใช้ต้องการ Dropdown เลือกเปลี่ยนรอบบิลย้อนหลังเพื่อตรวจสอบข้อมูลได้ทันทีในหน้าเดียว
5. **การแสดงหลักฐานการชำระเงิน (Slip URL)**:
   - ตารางรอบบิลแสดง URL ของสลิปดิบ ทำให้ตารางรกและไม่สะดวกต่อการตรวจหลักฐาน
6. **รูปแบบโมดอลรายละเอียดรอบบิลและการตรวจสลิป**:
   - การเปิดแถบข้าง (Side Sheet) ไม่สะดวกสำหรับการตรวจสอบความถูกต้องระหว่างตัวเลขทางบัญชีและภาพถ่ายสลิป ผู้ใช้ต้องการ Modal กลางจอแบบ 2 คอลัมน์ (Split View) ที่มีข้อมูลรอบบิลทางซ้าย และภาพสลิปทางขวา พร้อมปุ่มอนุมัติหรือปฏิเสธในตัว
7. **ความชัดเจนของคำเรียกหน้าบัญชีและเงื่อนไขการออกใบเสร็จ**:
   - ควรเปลี่ยนชื่อเมนูและหัวข้อหน้าเป็น "ใบแจ้งหนี้และรอบการเรียกเก็บเงิน" ให้ตรงกับความหมายจริงในระบบ
   - การดูใบเสร็จรับเงินต้องถูกจำกัดให้เปิดได้เฉพาะรอบบิลที่ได้รับการอนุมัติการชำระเงิน (`paid`) แล้วเท่านั้น หากยังไม่อนุมัติจะต้องแสดงสถานะปิดใช้งานพร้อมคำชี้แจง

## Decision
1. **แก้ไข School Detail Modal และลบปุ่มปิดซ้ำซ้อน**:
   - เปลี่ยนปลายทางการนำทางของปุ่ม "ดูรายการไซต์พลังงาน" เป็น `router.push('/sites')`
   - ลบเส้นกรอบแบ่งส่วนที่ซ้ำซ้อนใน `school-detail-modal.tsx`
   - นำปุ่ม "ปิดหน้าต่าง" ออกจากทุก Detail Modal (`school-detail-modal`, `audit-detail-modal`, `alert-detail-modal`, `user-detail-modal`, `notification-detail-modal`, `report-detail-modal`, `document-preview-modal`) โดยอาศัยปุ่ม `X` ปิดที่มุมขวาบนเป็นมาตรฐานเดี่ยว
2. **ขยายความกว้าง Site Telemetry Dialog บน Desktop**:
   - กำหนดคลาส `sm:max-w-5xl lg:max-w-6xl w-full sm:rounded-2xl` ให้แก่ `SiteTelemetryDialog` เพื่อ Overwrite ข้อจำกัด `sm:max-w-lg` ดั้งเดิมของ Shadcn Dialog
3. **ยกระดับ Document Preview Modal สัญญา PPA เป็น A4 Paper Draft PDF Preview**:
   - ออกแบบ Layout กระดาษ A4 สัดส่วนมาตรฐาน พร้อมหัวกระดาษตราประทับโครงการพลังงานแสงอาทิตย์
   - บรรจุข้อกำหนดสัญญาซื้อขายไฟฟ้า 20 ปี (Solar PPA), ข้อกำหนดทางเทคนิค, อัตราค่าบริการแบบขั้นบันได และกล่องลงนามทางการ 2 ช่อง (ผู้แทนโครงการ & ผู้แทนสถานศึกษา)
4. **เพิ่ม Billing Period Selector ในการพรีวิวใบแจ้งหนี้และใบเสร็จ**:
   - ติดตั้งตัวเลือก Select Dropdown ใน `DocumentPreviewModal` สำหรับรอบบิล 8 เดือนย้อนหลัง พร้อมฟังก์ชันคำนวณยอดเงินและเลขที่เอกสารใหม่แบบ Dynamic ตามรอบบิลที่เลือก
5. **เพิ่มปุ่ม "ดูสลิป" และ Lightbox Dialog ขยายดูสลิป**:
   - ใน `OperationTable` และ `OperationCardList` แทนที่ข้อความ Slip URL ด้วยปุ่มกระชับ "ดูสลิป" พร้อมไอคอน
   - เมื่อกดจะเปิด Dialog พรีวิวรูปภาพสลิปความละเอียดสูง พร้อมปุ่มเปิดดูภาพเต็มในแท็บใหม่
6. **พัฒนา Centered 2-Column Split-View Billing Detail Modal**:
   - สร้างคอมโพเนนต์ `BillingDetailModal` (`apps/web/features/billing/billing-detail-modal.tsx`) ขนาด `sm:max-w-4xl lg:max-w-5xl`
   - ฝั่งซ้าย: ข้อมูลรอบบิล, พลังงานที่ผลิตได้, ค่าพลังงาน, อัตราส่วนลด, ยอดสุทธิ และสถานะ
   - ฝั่งขวา: พรีวิวภาพสลิปการโอนเงิน พร้อมปุ่มขยาย Lightbox
   - แถบการกระทำด้านล่าง: ปุ่ม "อนุมัติการชำระเงิน" และ "ปฏิเสธสลิป" สำหรับ Admin/Owner
7. **ปรับชื่อหน้าและกำหนดเงื่อนไขการดูใบเสร็จ**:
   - ปรับชื่อหน้าเป็น "ใบแจ้งหนี้และรอบการเรียกเก็บเงิน" (Invoices & Billing) ใน `apps/web/app/(app)/billing/page.tsx` และไฟล์แปลภาษา `packages/i18n`
   - ใน Action Menu ของตารางและบัตรรายการ: อนุญาตให้กด "ดูใบเสร็จรับเงิน" ได้เฉพาะเมื่อ `status === 'paid'` หรือ `paymentStatus === 'approved'` มิเช่นนั้นจะปิดการใช้งาน (Disabled) และแสดงข้อความ "(ออกได้เมื่ออนุมัติแล้ว)"

## Consequences
- การเปิดดูรายละเอียดและการนำทางในระบบมีความสอดคล้องกัน ปราศจากลิงก์เสีย (Dead Link 404)
- ตารางตรวจสอบโทรมาตรและ Modbus Registers แสดงผลได้กว้างขวาง สบายตา
- สัญญา PPA อยู่ในรูปแบบโครงสร้าง A4 เสมือนจริง พร้อมนำไปใช้ในการพิมพ์หรือเชื่อมต่อระบบ Digital Signature ได้ทันที
- การตรวจสลิปโอนเงินสะดวกรวดเร็วในหน้าเดียวแบบ Split-View โดยไม่ต้องสลับหน้าจอไปมา
- กระบวนการออกเอกสารทางการเงินมีความถูกต้องตามหลักบัญชี ใบเสร็จรับเงินจะปรากฏเฉพาะรายการที่ชำระเงินและอนุมัติแล้วจริงเท่านั้น
