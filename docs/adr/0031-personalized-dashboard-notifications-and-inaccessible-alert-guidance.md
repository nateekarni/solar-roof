# ADR 0031: Personalized Dashboard Notifications and Inaccessible Technical Alert Guidance

## Status
Accepted

## Context
Previously, the dashboard card "การแจ้งเตือนล่าสุด" (Live Health / Recent Alerts & Notifications) queried the raw `alerts` table directly for all sites within the user's site scope without inspecting the user's role, permissions, or notification recipient configurations.
This caused major UX and security friction:
1. Business roles (Owner and Accountant) were shown raw equipment/hardware telemetry offline alerts (e.g. `แจ้งเตือน / Alert - offline`) without site names, operational context, or business notifications (e.g. invoices, receipts, payment confirmations).
2. When an Owner clicked on an alert, they had no access to the `/alerts` operational route (which is technical-only), resulting in confusion or forbidden access.
3. Relevant operational events generated by the system (invoices, receipts, workflows) were only visible in the notification bell popover and completely excluded from the dashboard summary.

## Decision
1. **Unified, Scoped Query in Dashboard Summary**:
   - `DashboardService.getSummary` replaces the raw `alerts` query with a union query combining:
     - `alerts`: Technical alerts visible to technical staff (`technical.alerts.view`), and to business staff (`owner`, `accountant`) **only if** they are explicitly designated as recipients in `operational_event_recipients`.
     - `notification_feed_events`: Business and workflow notifications (invoices, receipts, payment notices) visible to users who have business permissions or customer assignments for that site, and are configured as recipients.
   - Returned items include `id`, `title`, `detail`, `severity`, `status`, `occurred_at`, `siteName`, `destination`, and `kind`.
   - `alertActiveCount` counts active unacknowledged items across the user-visible list.

2. **Refactored Dashboard Alerts Card Layout**:
   - Each item row displays:
     - Top line: `[Icon] [Site Name] · [Title]` (with distinct icon per severity/kind: red destructive for critical/offline alerts, amber warning for alerts, primary blue for business notifications).
     - Bottom line: `[Detail / Doc No.] · [Formatted Time]`.
     - Right: `[renderStatusBadge(status, locale)]`.
   - Empty state: Clean `Bell` icon with "ไม่มีการแจ้งเตือนใหม่" (Thai) / "No new notifications" (English).

3. **Inaccessible Technical Alert Handling (Guidance Modal)**:
   - When a user clicks an accessible item (`canVisitPage(role, destination)`), navigation proceeds directly to `destination`.
   - When a business user (such as Owner) clicks an inaccessible technical alert (`!canVisitPage(role, destination)`):
     - It does NOT navigate to `/alerts`.
     - Instead, it opens a dedicated **Technical Alert Guidance Dialog** (`TechnicalAlertGuidanceDialog`) showing:
       - Header: "การแจ้งเตือนทางเทคนิค" / "Technical Alert"
       - Alert summary (Site Name, Title, Detail, Status badge, Timestamp).
       - Official guidance notice:
         * Thai: *"การแจ้งเตือนนี้เป็นข้อมูลทางเทคนิคของอุปกรณ์ในไซต์งาน กรุณาประสานงานเจ้าหน้าที่เทคนิคหรือผู้ดูแลระบบเพื่อตรวจสอบและดำเนินการแก้ไข"*
         * English: *"This is a technical equipment alert. Please notify the technical staff or system administrator to inspect and resolve the issue."*
       - Action button: "รับทราบ" / "Acknowledge" to dismiss.

4. **Add/Edit Site Modal Ergonomics**:
   - Removed `<legend>` dividing headers with full-width underline across all 3 tabs (Site, Customer, Billing).
   - Expanded tab triggers to full container width (`w-full flex-1`).
   - Simplified wizard navigation button labels to simply "ถัดไป" / "Next".

## Consequences
- Business users see meaningful notifications tailored to their role and explicit subscription settings rather than generic hardware noise.
- Equipment offline alerts intended for Owner awareness are presented cleanly with actionable escalation guidance rather than hitting dead-end routes.
- The dashboard overview feels cohesive, informative, and role-appropriate.
